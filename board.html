Traps already paid for

Each of these cost real hours. They are here so nobody rediscovers them.

Listing a digital product on Etsy

  1. The digital-file input does not exist until you click “Add file”. Search the page for a file input and you find only the photo uploader, and conclude the feature is missing. Three attempts died here.
  2. Set the category first. Until one is chosen Etsy treats the listing as physical, demands returns and delivery profiles, and the Digital option never appears at all.
  3. Copy every PDF to a staging folder before uploading. The originals are hardlinked and Etsy’s uploader refuses files with more than one link.
  4. A replaced photo lands last in the grid, and drag-reorder cannot be automated. Plan the order before you replace anything.
  5. The listing editor is atomic. Nothing goes live until “Publish changes”, and “Discard changes” undoes the lot — so the whole edit can be staged safely and reviewed before it reaches a buyer.

Building listing images on Windows

  1. Nothing errored, and every word rendered at 10 px on a 2000 px canvas. The font finder listed only macOS and Linux paths, so on Windows every path missed and the drawing library fell back to a bitmap font that silently ignores the size you ask for. Fixed — but the 13 live Caregiver Binder images still carry the hairline text.

Writing an image-generation prompt

  1. Numbers in a prompt do not work — proven twice on this machine. The prompt biases the output; the gate measures it. Never make the prompt pretend to be the gate.
  2. Describe appearances, not measurements. “Large open colouring spaces”, never “regions over 2.5 mm”.
  3. Stop writing banned-lists. They are a graveyard of previous failures that names the very things you do not want. One short exclusion sentence at the end, no more.
  4. Some nouns are structurally hostile — woven basket, brick, plank floor, patterned rug. Do not ask for them.
  5. Exaggerated scale is the one lever that raises the pass rate and the appeal at the same time. Add scale contrast, not detail.
  6. Wording cannot hold a character’s identity across generations. That needs reference conditioning, not a better sentence.

Standing rules

The parts of the Notion page that are not history. These do not expire.

How to answer

  • Dot points, ELI10, about half the usual length. Comprehensive on context, short on text.
  • Be a real critic — blunt, constructive, not encouraging by default. Point out flaws actively and reframe the problem rather than just answering it.
  • Do not execute unless 95% confident it will work. Verify first, then act.
  • Complex task → a visible todo list first. Never run on Fable unless told to — it costs twice Opus, which is a spending rule, not a quality one.

When she says “ask ChatGPT”

  • It never means a general chat. It means run the fixed vision review and judge the result on whether it will sell.
  • Use the prompt exactly as written. Do not reword it — rounds must stay comparable or the scores mean nothing.
  • What matters, in order: price a stranger would pay → the cover at thumbnail size → the verdict and its three fixes.
  • A low Beauty score is information. A problem with price, cover, or a claim the product does not honour is a blocker.
  • Ask for weaknesses and advice — never tell a reviewer to attack it, and never set a quota of criticisms. Quotas manufacture defects.

Before anything gets built

  • Read DECISIONS & DEAD ENDS first. If a row says do not retry, do not suggest it. Weeks have gone to AIs confidently re-proposing known failures.
  • Never mark Done without a passing QA check, and never check your own work. Self-approval is not a check.
  • Evidence means actual output, numbers, error codes. Never “looks good”. Write the actual failure, not the word “failed”.
  • Google and Gemini always go through Vertex, never the AI Studio key — it has no credit. Never change models silently inside a run.
  • A plain script is the default. An AI runs only when something must be decided. This board is one: scripts collect, a person decides.

How this board stays current

Three steps, and only the middle one needs a person.

Every few hours, automatic board_data.py reads the spend files, the gate registry and git, works out what has gone stale, and writes board_data.json. Plain script — no AI, no tokens, no dollars.
When a platform is read A person or a browser session updates board_facts.json with the new value and its reading date together. The script never invents one and never refreshes one.
One tool call Ask any interactive Claude session: refresh the handoff board. It pushes the JSON into this page’s store and every open copy updates.
Why the last step is not automatic

Measured 4 September 2026: a headless claude -p session has no Artifact tool. An earlier wrapper called it anyway, Claude replied “I don’t have access to an Artifact tool”, exited cleanly, and the wrapper logged a successful push that never happened. So the script writes BOARD_PUSH_NEEDED.txt instead of faking it. A false success is worse than a missing one.
