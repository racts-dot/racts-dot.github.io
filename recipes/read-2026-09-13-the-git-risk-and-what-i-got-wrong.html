The risk that ate two recipes — and the part of my own diagnosis that was wrong

13 Sep 2026. Nothing here has been changed. This is a description, not a fix.

⚠ First: I named the wrong culprit

In the plan I wrote yesterday I said this:

"your allow-list contains pre-approved git -C ~/testing stash push -u — and stash push -u sweeps up untracked files."

I read the rule properly today. It cannot do that.

   WHAT I SAID IT WAS          WHAT IT ACTUALLY IS
   ──────────────────          ───────────────────
   git stash push -u  *        git stash push -u -m
   a wildcard                  "pre-merge stash session f149cc15"
        │                              │
   fires on any stash          fires on THAT EXACT STRING
                               and nothing else

⭐ It is an exact-match rule tied to one dead session. It auto-approves one literal command that will never be typed again. It did not cause the loss, and it is not a standing risk.

⛔ So the honest position is: two recipes were orphaned by a git operation during the repo consolidation, and I do not know which one. I recovered them. I cannot name the cause, and I am not going to invent one twice.

What the audit actually found — all 31 rules, read today

31 auto-approved. Zero blocked. Zero set to ask.

Most are harmless — reading a Notion page, checking a yt-dlp version, taking a browser screenshot. Three are not narrow, and they are worth your eye:

RuleWhat it permitsWhere
Bash(python -c ' *)⛔ Run any Python at all, no prompt. The * is the whole languageclaude desktoi
Bash(git apply *)Apply any patch to any filehome folder
Read(//c/Users/soyan/**)Read anything in your user folderclaude desktoi

⭐ python -c '* is the widest one by a distance. Everything a delete, an upload or an overwrite needs is inside Python. An AI that wanted to do any of those has a door that does not knock.

⚠ I am not saying anything abused it. I am saying the door has no lock and you never chose that — it was accumulated one "always allow" click at a time.

The three options, and what each costs you

   1. A DENY LIST
      block: permanent delete, disk format, force-push
      cost:  a few seconds writing it. Nothing else.
      ⭐ these are things you never want done, by anyone, ever

   2. NARROW THE THREE WIDE RULES
      python -c ' *   ──►  delete it; let it ask
      cost:  more permission pop-ups, daily

   3. ONE SESSION PER FOLDER
      cost:  changes how you work. The biggest change,
             and the least certain to help

⛔ I have implemented none of them. Each changes how your machine behaves when you are not watching, and that is your call, not mine.

⭐ If you only do one, do the deny list. It costs you nothing in daily friction, because it blocks only things you would never authorise anyway.

What is safe right now, measured

All ten recipes✅ on disk, tracked in git, committed
The same ten✅ in Google Drive → READ BEFORE WORK
Untracked recipe files✅ none — that was the exposed state, and it is closed

⭐ The specific thing that bit us cannot bite the same way again: a tracked, committed, pushed, Drive-copied file has four homes. The lost pair had one.

The lesson worth keeping

When you find recoverable work in a dangling commit, recover it immediately. Do not write a plan about it first. I wrote the plan. The garbage collector ran. I had to write both recipes again from the transcripts.
